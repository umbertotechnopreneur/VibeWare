# VibeWare project context

Last consolidated: **7 October 2026**, Asia/Saigon.

## Repository purpose

This public repository maintains the VibeWare manifesto, approved identity, press assets and reusable templates. VibeWare is Umberto Giacobbi’s label for work shaped by human intent, executed with AI and evaluated under human responsibility.

The repository is the source for the brand and its documentation. It is not an application repository, software release channel or quality certification service.

## Established decisions

- Umberto Giacobbi coined **VibeWare** on 5 October 2026.
- The canonical tagline is `VibeWare = Human intent, AI, and plenty of tokens ;-)`.
- The approved source artwork is `Branding/vibeware-logo.png`.
- The approved visual direction is 1980s computing, lo-fi and pixel art without neon effects.
- The floppy and VW monogram are the primary symbol. Wordmark files in the press kit remain raster candidates rather than an approved vector master.
- The canonical manifesto URL is `https://umbertogiacobbi.biz/vibeware/manifesto`.
- Third-party motion reference material remains outside Git because redistribution rights were not established.
- The VibeWare name describes an approach to development. It is not a software licence, an endorsement or proof that a particular project passed specific checks.

## Project boundaries

Applications that use VibeWare branding remain separate projects. Each one owns its code, dependencies, licences, privacy obligations, releases and verification evidence. Application handovers, runtime data, private inventories, binaries, AI models, credentials, logs and user data do not belong in this repository.

The repository may document links to related work, including [ESP32 Luna Shell](https://github.com/umbertotechnopreneur/esp32-luna-shell), without importing that project or implying shared release status.

## Maintenance

Keep the manifesto concise and principle-driven. Keep practical identity, asset and reuse guidance in the press kit. Record durable repository decisions here. Add reusable material only when it serves more than one project, and place it in `templates/`.

Archived proposals preserve history and provenance; they do not become approved alternatives merely by remaining in the repository.
